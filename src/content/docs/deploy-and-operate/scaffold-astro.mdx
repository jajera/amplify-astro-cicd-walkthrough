## Starting point

You should already be in the cloned repo:

<FileTree>

- amplify-astro-cicd/ repo root (`pwd`)

Do **not** push commits straight to `main`. Use an issue, a feature branch, a pull request, wait for checks, then merge.

## Open an issue

Create a GitHub issue, for example: **Scaffold Astro sample and hygiene workflows**.

## Create a branch

```bash
git fetch origin
git checkout main
git pull origin main
git checkout -b feat/scaffold-astro
```

## Scaffold Astro

Scaffold **into this directory** (not a nested folder):

```bash
npm create astro@latest . -- --template minimal --install --no-git --typescript strict
```

Confirm a local build:

```bash
npm run build
ls dist
```

Keep the site minimal: one page is enough. The goal is CI/CD, not content design.

## Add amplify.yml

Create <Tooltip term="amplify-yml" label="amplify.yml" /> at the repository root:

```yaml
version: 1
frontend:
  phases:
    preBuild:
      commands:
        - npm ci
    build:
      commands:
        - npm run build
        - |
          if [ "${AWS_BRANCH}" != "main" ]; then
            printf 'User-agent: *\nDisallow: /\n' > dist/robots.txt
          fi
  artifacts:
    baseDirectory: dist
    files:
      - '**/*'
  cache:
    paths:
      - node_modules/**/*
```

Notes:

- `AWS_BRANCH` is set by Amplify (`main`, `staging`, or a PR branch name)
- Non-`main` builds write a disallow-all `robots.txt` so previews and staging are less likely to be indexed
- Artifacts come from `dist/` only - do not publish `node_modules`

Full reference: [amplify.yml](/reference/amplify-yml/).

## Add hygiene workflows

Create these under `.github/workflows/` before the first PR (best practice; required for commit message checks):

`.github/workflows/markdown-lint.yml`:

```yaml
name: Markdown Lint

on:
  pull_request: {}

permissions:
  statuses: write
  checks: write
  contents: read
  pull-requests: read

jobs:
  markdown-lint:
    uses: actionsforge/actions/.github/workflows/markdown-lint.yml@main
```

`.github/workflows/commitmsg-conform.yml`:

```yaml
name: Commit Message Conformance

on:
  pull_request: {}

permissions:
  statuses: write
  checks: write
  contents: read
  pull-requests: read

jobs:
  commitmsg-conform:
    uses: actionsforge/actions/.github/workflows/commitmsg-conform.yml@main
```

## Commit, PR, wait, merge

Commits must pass commit message conformance: lowercase type, imperative header, **body required**.

```bash
git add .
git commit -m "$(cat <<'EOF'
feat: scaffold minimal astro sample for amplify

Add Astro minimal app, amplify.yml, and markdown-lint plus
commitmsg-conform workflows for pull request hygiene.
EOF
)"
git push -u origin HEAD
```

Open a pull request into **`main`** (link the issue with `Closes #N`), wait for checks to pass, then merge (squash is fine).

```bash
gh pr create --title "feat: scaffold minimal astro sample for amplify" --body "$(cat <<'EOF'
## Summary
- Scaffold minimal Astro app with amplify.yml
- Add markdown-lint and commitmsg-conform workflows

Closes #<issue-number>

## Test plan
- [ ] PR checks green (markdown-lint, commitmsg-conform)
- [ ] Local `npm run build` succeeds
EOF
)"
gh pr checks --watch
```

Merge only after checks are green. Do not push to `main` directly.

<Aside type="caution">
Every later change in this lab follows the same path: issue → branch → PR → green checks → merge.
</Aside>
